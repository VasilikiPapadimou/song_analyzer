# Overview

Song Analyzer is an end-to-end AI pipeline that transforms raw song lyrics into a structured JSON representation.

Rather than asking an LLM to "analyze a song" and accepting free-form text, this project treats the language model as **one component of a larger AI system**.

The application:

- validates the input
- preprocesses lyrics
- constructs a structured prompt
- sends the request to an LLM
- parses the returned JSON
- validates the response against a JSON Schema
- enriches it with deterministic metadata
- stores reproducible outputs

The goal is not simply to generate song analyses, but to demonstrate how Large Language Models can be integrated into reliable software systems.

# Project Motivation

Large Language Models are incredibly powerful, but integrating them into production software requires much more than calling an API.

This project explores questions such as:

- How can we reliably process unstructured text?
- How do we validate AI-generated outputs?
- How do we separate deterministic logic from probabilistic reasoning?
- How do we design AI pipelines that are reproducible and maintainable?

The result is an end-to-end AI pipeline that emphasizes reliability, reproducibility, and structured processing rather than treating the LLM as a black-box text generator.

# System Design Decisions

This project was intentionally designed as an AI system rather than a simple LLM wrapper.

The objective was to separate deterministic software engineering responsibilities from probabilistic AI reasoning, making the pipeline more reliable, reproducible, and maintainable.

Key design decisions include:

- **Separation of responsibilities**
  - Python handles orchestration, validation, file management, metadata generation, and persistence.
  - The LLM is responsible only for semantic analysis.

- **Structured outputs instead of free text**
  - The LLM is instructed to return structured JSON instead of natural language paragraphs.
  - This allows downstream processing without additional parsing.

- **Schema-first validation**
  - Every AI response is validated against a predefined JSON Schema before it is accepted.
  - Invalid outputs are rejected instead of silently propagating through the pipeline.

- **Deterministic metadata**
  - Information such as processing timestamps, prompt version, model version, and song metadata is generated by Python rather than inferred by the LLM.

- **Reproducible outputs**
  - Every analysis is stored using a deterministic folder structure to make experiments repeatable and easy to inspect.

- **Modular architecture**
  - Input processing, prompt generation, LLM communication, parsing, validation, logging, and file management are implemented as separate modules to improve maintainability and testability.

# Installation

Clone the repository:

```bash
git clone https://github.com/VasilikiPapadimou/song_analyzer.git

cd song_analyzer
```

Install the project dependencies:

```bash
uv sync
```

Create a `.env` file in the project root:

```text
OPENAI_API_KEY=your_api_key_here
```

Run the application:

```bash
uv run python src/_main.py
```

# Validation Pipeline

One of the primary goals of this project is demonstrating that LLM outputs should **never be blindly trusted**.

Every AI response passes through multiple validation stages:

```
LLM Response
      │
      ▼
JSON Parsing
      │
      ▼
Schema Validation
      │
      ▼
Metadata Assembly
      │
      ▼
Final Schema Validation
      │
      ▼
analysis.json
```

This design separates deterministic software logic from probabilistic AI reasoning.
